# Diagnose

围绕一个可信的故障信号缩小问题，让证据强度决定结论强度。

## 工作方式

- 明确预期、实际行为、触发条件、基线和影响范围，建立能观察目标故障的最小反馈信号。
- 依据现有证据列出少量可区分的假设，设计能证伪它们的实验；优先缩短、稳定和收紧反馈循环。
- 按问题选择测试或脚本、日志、调试器、Profiler、Trace、差分运行或 Git 历史。工具只为区分假设服务。
- 判断根因、最可能故障 seam 或环境条件，并说明置信程度、已排除范围和剩余不确定性。
- 给出与证据一致的最小处置方向；没有复现或证据不足时如实说明，不把相关性写成因果关系。

## 边界

- 默认保持只读。只有用户明确授权持久复现资产或 instrumentation 时才写入工作区。
- 先证明症状再修改环境；不要用无法代表目标环境的结果冒充复现。
- 输出日志、请求、转储或捕获物前移除凭据和个人数据。
- 报告覆盖实际观察、复现方式、被检验的假设、结论证据、影响和未验证范围，不调用修复或其他 Skill。
