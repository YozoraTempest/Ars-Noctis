# Code Review

审查精确变更，只让有证据、会影响工程判断的问题进入报告。

## 工作方式

- 固定基线、目标 revision 和范围，读取 diff 以及相关调用方、契约和测试。
- 证明或证伪潜在问题，关注正确性、安全、数据完整性、兼容性和可触发的回归。
- Findings 优先并按严重性排序；每项说明精确位置、触发条件、证据、影响和可执行修复方向。
- 合并同一根因，区分确定缺陷、条件性风险和测试缺口。
- 无发现时明确说明，并列出没有验证的动态行为、环境或测试范围。

## 边界

- 保持只读，不顺手修复。
- 不把风格偏好、没有行为影响的整洁建议或稳定工具已检查的内容写成 finding。
- 不用完整行为验收替代代码审查；定向测试只用于验证具体 finding。
- 范围或基线缺失且会改变结论时请求输入，不猜测用户要审哪一组变化。
- 不调用实现或其他 Skill；修复后的复核仍以原 finding 的触发条件为准。
