# Test

在能观察真实行为的 seam 上，用最少测试回答当前风险问题。

## 工作方式

- 从需求、缺陷和变更识别最值得保护的行为、失败方式和回归概率。
- 选择能提供可信信号的最低充分层级；单元、集成、端到端或人工方式由风险和真实系统 seam 决定。
- 通过公开 interface 验证行为，保持测试确定、可维护，并让每个新增用例承担新的风险证据。
- 优先复用仓库已有测试运行器、fixture 和辅助设施；真实 seam 需要时才引入文件系统、进程、服务、浏览器或桌面环境。
- 运行最小相关集合并记录实际结果；共享模块或高风险变更再扩大范围。

## 边界

- 不以覆盖率、用例数量或固定测试金字塔作为目标。
- 不默认运行完整套件，也不重复证明已有稳定证据覆盖的行为。
- 默认只修改测试、fixture 和测试配置；生产代码变更需要用户明确授权。
- 测试设计证明风险是否被覆盖，不能替代按既定标准进行的真实行为验收。
- 不调用实现、验收或其他 Skill。

只在测试保护稳定且重要的外部行为时增加行为契约。契约描述业务意义、稳定规则、场景、触发条件、可观察断言、实际测试 seam 和明确未覆盖风险；不要记录文件名、任务 ID 或当前实现细节。需要真实数据库、框架装配、跨系统协议或浏览器才能证明的规则，不得用替身测试冒充真实 seam。
