# Behavior Contract

只在测试保护稳定且重要的外部行为时使用本格式。Contract 紧邻测试声明，每个结果必须有真实断言：

- `Summary`：行为结果及业务意义。
- `Feature`、`Business Rule`、`Scenario`：稳定领域语义，不写文件名、任务 ID 或实现方案。
- `WHEN`、`THEN` 和必要的 `AND`：触发条件与实际断言的可观察结果。
- `Test Boundary`：测试实际经过的公开边界。
- `Not Covered`：该测试不能证明的具体风险；不得用空泛措辞掩盖边界。

先确认 Contract 描述的是需求或架构约束，而不是当前实现细节。普通工具函数、显而易见的输入输出和短期实现细节不使用 Contract。

如果规则需要真实数据库、框架装配、跨服务协议或浏览器才能证明，选择相应等级或明确保留风险，不用替身测试冒充真实边界。新增 Contract 不授权批量改写无关历史测试。
